# Market scan, November 2026

Why TaskWing v2 sits where it does. The figures come from secondary sources and some conflict; treat them as rough.

| Layer | State | Implication |
|---|---|---|
| Sandboxes | E2B, Daytona, Modal, Vercel, Cloudflare, AWS AgentCore, Fly Sprites. Heavy funding (Modal reported $355M Series C) and hyperscalers moving in. | Turning into a commodity. Plug in, don't build one. |
| Sandbox standards | Google Agent Substrate + gVisor to CNCF (Nov 2026), OpenSandbox to the Agentic AI Foundation (Oct 2026), Docker Sandbox Kits (experimental), Kubernetes Agent Sandbox (v1.0.4). None widely adopted yet. | Keep the Box adapter small so the winner is easy to adopt. |
| Agent interface | ACP (Zed): Gemini CLI native; Claude Code and Codex through adapters; registry counts of 25-60 agents. | Use ACP as the Agent adapter. |
| Local orchestrators | Conductor, Agentastic (claims 50+ agents), T3 Code, Claude Squad, Composio Agent Orchestrator. All worktrees on one machine. | Crowded. No tool found that shows hundreds of agents. |
| Control planes | GitHub Agent HQ: agents from several vendors, one dashboard, governance. One task to one PR, on GitHub. | Biggest threat. TaskWing's difference: one goal to N agents to one verified PR, any sandbox, self-hosted, credentials kept out of boxes. |

## Sanductor (prior art, read at commit 6ebed5d)

macOS SwiftUI cockpit by Mike McQuaid, AGPL. One agent, one worktree, one PR, driven by a human. No planner, no combine. Ideas only (AGPL and Swift cannot go into this MIT Go project). Ideas taken into `PRINCIPLES.md`: credentials out of the sandbox, derive state, hostile worker output, claim before send, trusted feedback only, events over polling.
